It contains no private message IDs or machine paths. Private provenance can be connected locally through the corpus/lead ledger.

Keep a comparison ledger per capability: announcement, demonstration, available source, inspected source, executed fixture, accepted implementation. Those are independent evidence states. Record source/build pins, original fixture inputs, differences, and whether the current SED fork already implements the idea. Correcting an old summary should not erase the dated historical report.

Suggested fixture queue: UV alignment across non-square/mirrored surfaces; connected extrusion and reference preservation; whole-mesh decomposition refusal; W/RGB save/reopen and float32 readiness; ARCH transforms/resource identity/occlusion; ordered frames and event bindings; received-versus-applied runtime revisions; unknown/ambiguous resource or geometry targets. Use small original assets and compare observable behavior before adopting another implementation.
