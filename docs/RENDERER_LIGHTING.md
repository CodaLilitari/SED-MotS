# Renderer lighting and shader verification

The mesh renderer carries four independent lighting components: monochrome plus red, green, and blue. `MeshVertex` retains its previous position, normal, RGB, and UV offsets; the monochrome float is appended at byte 44, giving a 48-byte stride. `RenderScene.LightingMode` selects which baked channels the shader uses. This does not change saved JKL lighting data.

- For textured materials in the OpenJK preview profile (`UsePaletteLightRamp = false`), `Mono` multiplies the base palette RGB by the scalar light, following the accelerated engine's main albedo path. `UsePaletteLightRamp = true` retains an explicit CMP comparison profile: it selects row `floor(63 * clamp(mono))` of the sector CMP's 64-row light table, then resolves the resulting index through the master palette. Bare `RenderScene` instances default to that earlier tool profile; level scene assembly selects the OpenJK profile.
- For textured Gouraud materials, `Rgb` resolves the unshaded palette index through the master palette, then multiplies the color by the three independently clamped RGB components. The monochrome component does not multiply RGB.
- Solid-color MATs carry `IndexedTexture.IsSolid`. Unlike textures, they resolve through the sector CMP's own palette as well as its ramp: `rdCache_SendFaceListToHardware` reads `colors[]` and `lightlevel[]` of the face's colormap, which `sithRender` sets to the sector's CMP for surfaces and things. Without a resolved sector CMP they use the master palette and default ramp. The CMP tint that rdCache then applies is not modeled. Gouraud RGB uses each channel of the CMP row-zero palette baseline plus `255 * channel - 0.5`, clamped and truncated to a byte. This conversion occurs per vertex before interpolation. Solid monochrome also resolves the CMP per vertex before interpolation; unlit/diffuse solid faces use monochrome even in RGB display mode. Solid palette index zero remains a visible color.
- `Submesh.LightMode` carries the effective face/mesh light mode. Mode zero bypasses the ramp and uses the original palette entry, even when the top ramp row is not identity.
- `Submesh.UseMonochromeLighting` selects the ordinary-model scalar draw even within a MotS RGB scene. A world/model pair can share its material and CMP descriptors while retaining independent per-draw channel selection. This override does not change the stored alternate RGB values.
- 16/32-bit MATs carry decoded RGBA8 in `IndexedTexture.Rgba` and upload as `R8G8B8A8Unorm`. They bypass the palette and every ramp in both profiles: Gouraud `Rgb` multiplies the texel by the three RGB components, other modes multiply it by scalar light, and fullbright, sky and editor full-bright show the texel unchanged. A masked (`alpha_en & 1`) or translucent draw discards texels with alpha below one half, as the indexed path discards index zero.
- Flat marker and selection drawing keeps its existing direct vertex-color path. Sky and the editor's full-bright override use full light in both modes.

Scene assembly is responsible for supplying the correct surface/model channels, ambient and extra-light terms, light modes, and validated architectural-light bindings. The GPU stage does not infer those inputs. These static preview paths do not by themselves establish gameplay lighting parity, dynamic-light behavior, transparency-table fidelity, or support for every engine rendering backend.

Architectural bindings now use the shared `ArchitectureBindingValidator` also used by resource-aware agent and GUI exports. The source parser retains bounded all-LOD topology metadata: geoset zero must match exactly and later LODs must fit the available ARCH array prefixes. Rendering still draws geoset zero. Missing topology, invalid bindings or incompatible native fingerprints fall back to model base/sector light with diagnostics; strict snapshots refuse them. Missing historical fingerprints are reported separately and do not invalidate otherwise compatible current topology. Parsed model geometry that no longer matches its captured shape cannot reuse that shape for preview binding.

Textured RGB currently interpolates floating-point light. The inspected accelerated engine truncates `255 * light` to vertex bytes after CPU clipping and applies optional tint/effects to those bytes; reproducing only the quantization without the same clipping order would still differ at generated clip corners. That quantization/clipping behavior and the engine's separate emissive-luminance path remain explicit limits of this preview. Solid-material vertex conversion is tested with gradients, but this is not a claim that the complete clipping pipeline is pixel-identical to the engine.

JK has one display palette for textures, the level's first World Colormap: OpenJKDF2's GL renderer uploads `colormaps[0]` as the world palette for every texture. `SetColormap` installs that master palette (and the default light ramp). `MasterColormap.Resolve` picks World Colormap 0, falling back to `dflt.cmp` with a stated problem and never to a later sector colormap; lit snapshots, the editor and the probe tools all use it (`ResolveFromArchives` reads GOBs in precedence order). Every textured material descriptor samples the master palette, and `SetColormap` rewrites them all. `Submesh.Colormap` selects a sector CMP independently of its material; a texture uses only that CMP's light table, while a solid color uses its palette too (see above). Resolving each sector's own palette for textures caused magenta speckle in community levels whose sectors all use `dflt.cmp` under a different World Colormap 0 (Massassi Egypt: `03house.cmp`; Shadow Caverns: `15maw.cmp`). The renderer shares a material's texture across CMPs and uses a separate descriptor set for each material/CMP pair. `SetScene` accepts a `ColormapLookup` alongside the material resolver. A missing named CMP produces a diagnostic and uses the master palette with the default light ramp; a malformed palette or light-table length is rejected. Callers should display `SceneRenderer.Diagnostics` after loading. `UpdateGeometry` reloads resources when an edit introduces a new material/CMP pair.

The accelerated engine converts its stored 90/255 alpha into an effective **165/255 opacity**. The preview now uses that effective opacity, retaining accumulated destination alpha. This corrects the earlier checkpoint's direct use of 90/255; see the [source contract](audit/MOTS_TRANSPARENCY_CONTRACT.md). MAT masking comes from the selected texture's `alpha_en & 1`. A masked or translucent indexed texture discards source index zero before CMP mapping; opaque unmasked index zero and solid color zero stay visible. The first cel's texture ID is respected, including preceding mip chains, whose sizes follow the MAT's bits per pixel. 16-bit MATs decode from their declared channel fields, or as OpenJKDF2's RGB565 (ARGB1555 when masked) when a legacy header declares none; a masked 16-bit MAT whose declared RGB leaves bit 15 free uses bit 15 as its mask, as the engine's ARGB1555 upload does. 32-bit MATs need a declared layout. Partial or overlapping layouts and other depths are refused. Truncation follows the retail mip fallback: textures before the selected one must be complete, and the selected texture's mip count must fit its dimensions and its mip 0 must be complete, or the MAT is refused; when only a later mip of the selected texture is short, `MatFile` decodes mip 0 and sets `MipFallbackNote`, which lit snapshots report as an asset notice. Retail JK reads mips unchecked but selects one per face by depth against the JKL's MipMap Distances (`rdCache.c`, `rdNRaster.c`), so it shows mip 0 only on nearby faces; SED draws mip 0 at every distance. Mixed solid/textured cel tables remain outside this decoder.

Adjoined masked/translucent world surfaces disable depth writes; ordinary translucent surfaces/models retain them. Every adjoined surface is also drawn only from in front of its plane (`RenderLightingState.SingleSidedBit`): the engine skips any level surface whose plane distance to the camera is not positive (`sithRender.c`), and an adjoined surface's coplanar mirror covers the other side. Drawing both faces of a pair double-sided made them z-fight, as on Atlantis's water, whose upward faces adjoin unlit downward `dflt.mat` mirrors (black voids and stripes), and blended translucent pairs twice. The test uses the vertex normal, which world surfaces set to the face normal; a zero normal stays visible. Non-adjoined surfaces stay double-sided so the editor can show geometry from outside. Blend and depth-write pipeline states are independent. Deferred triangles are ordered on every frame by minimum forward camera depth, allowing separate faces sharing a material to interleave. This is editor triangle sorting: the engine sorts clipped faces, and exact ordering at frustum boundaries or intersections is not established. Large-scene interactive performance also needs measurement; this path currently creates per-triangle deferred draws. The engine ignores authored face flag `0x20`, so this preview does not claim the Delphi editor's depth-write override is implemented. Sky projection/depth remains separate work.

`RenderScene.CullWorldBackFaces` (lit snapshot `cullBackFaces`, default off) extends that rule to every level surface: `SceneAssembler` marks world submeshes `Submesh.WorldSurface`, and `RenderLightingState.SingleSided` sets bit five for an adjoined submesh, or for any world submesh when the cutaway is on, never for a flat draw. Models never get the bit, because 3DO vertex normals are smoothed vertex normals, not face facings. From outside a closed room the ceiling and the walls facing away then vanish and the floor shows: Wren's "doll's house" preview.

Cameras can be perspective or orthographic (`Camera.Projection`, `Camera.OrthographicHeight` world units tall; `Mat4.Orthographic` maps view-space `z = -near` to depth 0 and `-far` to 1 with Vulkan's Y flip). A camera whose pitch is exactly ±90° uses its `CameraUp` for the view basis, so a plan view has +Y up and +X right; non-vertical cameras produce the same matrices as before. The renderer receives a `RenderEye`: the push constant `camPos` (byte 64) carries `(position, 0)` for perspective, as before, and `(unit direction toward the camera, 1)` for orthographic. With `w = 1` the vertex shader's facing value is `dot(normal, towardCamera)`, independent of the vertex position, because every ray is parallel; the fragment shader's ceiling sky projects each fragment along the view direction onto the sky plane instead of casting from an eye point, so an orthographic plan shows the ceiling sky independent of the sky surface's height. Deferred translucent ordering already used `RenderDrawOrder.MinimumDepth`, which handles both projections. Lit snapshot `fullbright` calls `SetBrightness(1)`, the editor's full-bright path, which draws indexed, solid and true-colour materials at their unlit palette entry or texel.

The final push word at byte 156 packs RGB selection in bit zero, solid-material selection in bit one, OpenJK textured scalar modulation in bit two, MAT masking in bit three, true-colour texture selection in bit four, single-sided world surfaces (adjoined, or all world surfaces with the cutaway) in bit five, and effective light mode in bits 8–15. The complete push range stays 160 bytes. Palette and light-ramp descriptors are visible to both shader stages so solid lighting can resolve before raster interpolation.

Both GLSL sources and compiled SPIR-V files are checked in. A normal build verifies their SHA-256 values against `Shaders/ShaderHashes.props`, so editing GLSL without refreshing the compiled binaries fails the build. No shader compiler is required just to build an unchanged checkout. To regenerate with installed tools:

```powershell
./tools/Compile-Shaders.ps1 -Compiler glslangValidator -Validator spirv-val
```

An existing WSL distribution can run the tools instead:

```powershell
./tools/Compile-Shaders.ps1 -WslDistribution Ubuntu `
  -Compiler /absolute/linux/path/glslangValidator `
  -Validator /absolute/linux/path/spirv-val
```

The script targets Vulkan 1.0, compiles all four shaders to a fresh directory under `build`, and runs `spirv-val` before replacing any committed binary. It then regenerates the hash file and writes a receipt containing tool versions and source/binary hashes. `-Check` repeats compilation/validation and requires byte-identical committed SPIR-V without updating it. Compiler versions can change output bytes; review intentional compiler updates together with regenerated binaries and receipts.

`RendererLightingLayoutTests` checks the actual packed vertex bytes, packed draw state, and strict CMP sizes. `dotnet/tools/Sed.LightingProbe` exercises the real Vulkan mesh pipeline offscreen with original synthetic textures and geometry. It checks independent mono/RGB behavior, channel clamping, full-bright and flat drawing, simultaneous CMPs on one material, CMP-only edits, that a sector CMP never replaces the master palette for a texture and that a new master palette reaches sector-ramp descriptors, that a solid color beside that texture uses the sector CMP's own palette in fullbright, ramp and RGB-baseline shading (and keeps it when the master palette changes, or falls back to the master palette when the sector CMP is unresolved), missing-CMP diagnostics, and rejected palette updates. True-colour cases cover scalar and RGB modulation, fullbright, masked and translucent discard, translucent blending and independence from the master palette. Facing cases check that an adjoined face is drawn only from in front, that its mirror takes over from the other side, that a coplanar translucent adjoin pair blends once, and that non-adjoined faces and zero normals stay double-sided. Orthographic and cutaway cases check that an orthographic eye decides facing by its direction from either side of the plane, that a direction-less orthographic eye is refused, that the cutaway culls an ordinary world face seen from behind while a model face stays, that fullbright shows the palette entry or texel of an unlit face, that an orthographic quad covers exactly its expected pixel columns and does not move when geometry slides along the view axis, and that the orthographic ceiling sky does not depend on the sky surface's height. It also contrasts OpenJK scalar modulation with CMP comparison, updates the profile without reloading a material, and draws ordinary scalar models beside RGB world geometry using the same MAT/CMP. Solid-material cases include distinct baseline channels, row truncation, nonidentity fullbright ramp bypass, index-zero visibility, hardware alpha, and gradients that distinguish per-vertex conversion from per-fragment conversion. It requires a new output directory, saves pixels and a receipt, and never launches the editor UI or game.

`dotnet/tools/Sed.TransparencyProbe` adds independent framebuffer-composition expectations, opposite cameras, interleaved same-material geometry, the zero-index masking matrix, solid-zero preservation, opaque cutout depth, all blend/depth pipeline choices, stable ties, and shared-material state updates. It also runs without a window or game assets and saves its frames and receipt to a new directory.
