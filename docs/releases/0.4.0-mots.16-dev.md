# SED MotS 0.4.0-mots.16-dev

Published September 30, 2026. This Windows x64 development prerelease adds
portable updates, shared dynamic vertex-color readiness diagnostics, and a
research-backed Codex level-design workflow. The self-contained package includes
the editor, `sed-agent` CLI and `sed-mcp` host.

[Download the editor and corresponding source](https://richard-pemberton-research.darkahn.chatgpt.site/downloads/#sed-mots)
or [get the Codex skill and research pack](https://richard-pemberton-research.darkahn.chatgpt.site/projects/jk-mots-level-workflow/).

## Changes

- The Windows editor checks update metadata in the background, with a 24-hour
  cache and a manual Help menu check. Installation verifies size and SHA256,
  extracts to a separate portable directory, and retains the old installation.
  Restart saves the level and requires the new process to acknowledge its exact
  recovery-file hash after opening it. Existing shortcuts still point to the old
  copy; update them to the displayed new directory when ready.
- GUI, CLI and MCP share a dynamic vertex-color readiness report based on the
  exact JKL output the writer would save. It distinguishes inspected retail
  compaction behavior from current OpenMotS layout handling, reports numeric
  uncertainty, and makes no automatic color perturbation.
- `jk-mots-level-workflow` 1.0.0 connects twelve original research findings to
  schema discovery, headless authoring, guarded plan/apply, readback, offscreen
  previews and explicit runtime checks. Its private corpus tooling tracks exact
  provenance, review status and known leads, including the announced C++ SED
  rewrite. Its reference updater preserves local modifications and does not
  replace scripts, executable tools, private evidence or local configuration.
- The release includes the prior shared UV/placement workbench. The existing
  typed MCP adapter and CLI support the workflow without another generic wrapper.
- Source archives now ignore inherited Windows Git line-ending settings.
  The MCP interruption test observes receipts through the supported API so its
  own file reader cannot block journal replacement on Windows.

## Validation and boundaries

The clean build passed 1,594 Core and 271 MCP tests with zero build warnings or
errors. Focused validation passed 169 headless GUI checks, 41 updater tests,
25 workflow/corpus tests, and 40 packaged diagnostic assertions across 11 CLI
and eight stdio MCP calls. The packaged general MCP workflow completed 67 tool
calls; PLAY authoring completed 139 and TOOL workbench completed 132 calls.
The independent byte audit matched all 864 source files to Git blobs and
957 manifested Windows payload files to the exact archive/extracted set
(958 physical files including its manifest).

Anonymous public checks verified 26 downloadable payloads byte for byte and
the workflow page's original HTML with the hosting platform's added script.
The actual packaged Core updater independently downloaded and staged the
158,261,511-byte public package through each configured feed URL, preserved the
old test files and refused an equal-version update. A separate original
fixture exercised process launch; headless GUI tests cover recovery acknowledgement.
The final public-package probes deliberately did not open the graphical editor.

The completed external diagnostic review was reconciled with executed
counterexamples. The external updater review reached its 900-second limit
without a returned answer; it is not counted as approval. Independent local
updater review and verification completed.

Raw Discord captures and copied forum posts are excluded from the public skill
and research payloads. The private index remains outside Git. Acquisition,
review, source evidence and runtime evidence remain separate. This release
does not establish new retail gameplay parity or full MotS renderer coverage.
The separate paused PLAY-01 review handoff remains paused.
