# SED MotS 0.4.0-mots.17-linux.1

This native Linux x64 distribution continues the CodaLilitari fork from
`ff88182`. It retains the .NET 10 / Avalonia editor and shared authoring model,
and packages native self-contained `Sed.App`, `sed-agent` and `sed-mcp`
executables. Start with [the Linux guide](../LINUX_QUICKSTART.md).

## Changes

- Native editor launch from the terminal, a desktop entry or a file argument.
  Recent files respect Unix filename case, settings remain per-user, and the
  default project directory falls back to the user's profile when Documents is
  unavailable.
- Native OpenJKDF2 discovery and explicit executable selection. Save and Test
  uses the shared launch planner and direct argument lists. Explicit existing
  Wine/custom shell templates retain their configured behavior.
- The MCP server finds its sibling `agent/sed-agent` automatically on Linux.
  Non-rendering CLI/MCP operations run without DISPLAY, Vulkan or an API key.
- Linux create-only output publication uses
  `renameat2(RENAME_NOREPLACE)`. Concurrent writers cannot replace one another's
  successful output. An unsupported filesystem fails explicitly.
- The existing scene renderer checks the device's push-constant limit before
  creating rendering resources. Devices with fewer than 160 bytes receive a
  diagnostic instead of an invalid pipeline; Mesa lavapipe is the tested CPU
  rendering route.
- Linux build/package/verify tools, cwd-preserving launchers, an optional
  create-only user desktop installer, dependency notices, source/history and
  checksums. Packaging starts from committed source and binds verification to
  a clean Git commit and the selected SDK.

## Evidence and package identity

The source work has passed the full Core suite (1,615 tests), MCP suite
(273 tests), native/Windows-policy launch contracts and 175 headless UI checks.
Regressions include competing Linux writers, unsupported renderer limits,
native default worker resolution, Unix paths, actual synthetic process argv,
GUI startup/opening and Save and Test behavior.

With Mesa CPU rendering, the original full-scene probe produced
33,195/307,200 lit pixels. The guarded UI probe also completes on the
unsupported SwiftShader device by refusing its scene renderer safely; that
result is a refusal check, not rendering success. The graphics build gate
requires the full scene probe in addition to the editor integration checks.

Distribution acceptance is recorded alongside the binary archive rather than
embedding a self-referential source hash here. Check:

- `build-receipt.json`: source identity, SDK, test projects and build status.
- `package-receipt.json`: self-contained target, exact commit and archive hash.
- `verification/verification.json`: relocated CLI, no-display MCP, reviewed
  edit/refusal and default-worker snapshot results.
- `SHA256SUMS.txt`: binary archive, corresponding source and complete history.
- The handoff verification report: actual native X11 startup, visual inspection,
  broader packaged workflows and remaining limitations.

The package's `PROVENANCE.json` also identifies its exact source archive and
history bundle. Linux CI uses the same public entrypoints. A local passing
receipt does not imply that a remote CI job has run.

## Compatibility boundaries

The binary target is glibc Linux x86-64. The .NET runtime is included; native
system libraries and a compatible Vulkan driver are separate dependencies.
Desktop rendering and explicit snapshots require Vulkan 1.2 and at least
160 bytes of push-constant storage. The tested SwiftShader driver reports
128 bytes and is unsupported; the tested Mesa lavapipe device reports 256.
No performance equivalence or support for untested GPUs, musl or ARM64 is
claimed.

Game engines, retail assets and community levels are not bundled. Native
process tests use original synthetic executables; renderer and editor tests
are not gameplay or retail-renderer validation. Windows launch semantics are
covered under an explicit policy on Linux, without a new Windows desktop run.
Linux package updates are side-by-side installations; the existing automatic
updater remains Windows-only. Existing Windows .16/.17 milestone evidence is
preserved and is not replaced by this Linux build.
