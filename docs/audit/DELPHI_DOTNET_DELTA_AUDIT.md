# Delphi / C# history and semantic delta audit

Inspected 2026-09-09. This is a read-only history and source audit requested before packaging the current C# editor. No build, editor, game, or downloaded program was executed for this audit. Only this report was added. Remote branches were fetched without checkout changes or pushes.

## Finding

The C# fork did **not** branch from a substantially older, unrelated Delphi history. It shares a precise common ancestor with `smlu/SED`. The only upstream-main commit absent from the pinned C# fork is a native plugin SDK header correction. The useful gaps are mainly **older Pascal behavior that was inherited as source but not translated into the C# implementation**.

There is also a separate local Delphi improvement branch from this project. Its additional MotS changes are not upstream `smlu` commits and must not be described as such. Several were reimplemented in C#, but its resource-aware architectural-lighting export guard is stronger than the C# guard. The initial findings and commit table below retain their inspection-time status; the following [post-audit disposition](#post-audit-disposition-2026-09-09) records subsequent fixes verified from source.

## Confirmed gaps to act on

These findings were sent to the parent task during inspection. They describe the inspected snapshot; subsequent remediation should be recorded explicitly rather than silently changing an “unported” row into a historical claim of completion.

1. **Legacy JED-generated JKL light rows are silently omitted.** Upstream `2de8b58` added the `index: layer x y z intensity range` fallback. After removing the index, that is six fields. Current [JklParser.LoadLights](../../dotnet/src/Sed.Formats/Jkl/JklParser.cs) skips every row with fewer than seven fields and then implements only the seven-field and ten-field SED layouts. For example, `0: 2 1.0 2.0 3.0 0.75 8.0` contributes no editor light. Retaining raw section text on an untouched save does not restore the missing in-memory light; a later LIGHTS regeneration can drop it. This is distinct from the native `.jed` importer, which handles a different 10/12-field format. Implement explicit six/seven/ten-field classification, reversed legacy intensity/range ordering, bounded counts, and clear malformed-row errors. Test unequal range/intensity, nonzero layer, all three layouts, truncation, surplus fields, and no-edit versus forced regeneration.
2. **Transparent polygon sorting was not ported.** Upstream corrected both the complete sort range and camera-relative polygon distances. Current [SceneAssembler.Build](../../dotnet/src/Sed.Rendering/SceneAssembler.cs) groups by material/CMP/flags and orders only opaque versus translucent; [SceneRenderer.Render](../../dotnet/src/Sed.Rendering.Vulkan/SceneRenderer.cs) draws translucent batches without a camera-dependent sort. A material batch can combine near and far faces, so simply sorting whole material batches would remain insufficient. Use per-face or per-triangle transparent draw ranges, sort back-to-front per camera, and test overlapping differently colored translucent geometry with reversed camera/order. Preserve opaque material batching.
3. **Sky depth-write handling was not ported.** Upstream `4139b5b` marks ceiling sky with `FF_ZWriteDisabled`. The C# assembler emits a `SkyMode`, but the opaque Vulkan pipeline always enables depth writes and has no per-submesh depth-write state. This also omits authored `FaceFlags.ZWriteDisabled` behavior. Add explicit depth-write control and test a sky face against model geometry behind its authoring polygon. The Pascal commit comment calls this disabling depth testing, but the code sets a *depth-write* flag; those are different operations.
4. **JK/MotS texture-clamp behavior diverges from Pascal.** Upstream `1d524be` clears clamp-U/V on non-IJIM world surfaces, and `adc5de3` hides those options outside IJIM. Current C# world and model assembly applies `FaceFlags.TexClampX/Y` unconditionally. This is a confirmed editor-to-editor divergence, not by itself proof of the correct current OpenJKDF2 behavior. Check the target engine/profile before choosing retail-compatible wrapping versus an OpenJK extension. Preserve file bits regardless of the preview decision. Test UVs outside `[0,1]` with the same face bits in JK, MotS, and any supported IJIM path.
5. **GUI horizon offset plumbing is incomplete.** The shared Pascal sky implementation uses the level's horizon offsets. Current [AgentSnapshotRunner](../../dotnet/tools/Sed.Agent/AgentSnapshotRunner.cs) supplies them to `SetSky`, while [VulkanView.SetLevel](../../dotnet/src/Sed.App/VulkanView.cs) supplies only ceiling arguments. Nonzero horizon offsets therefore differ between GUI and CLI previews. Both C# paths additionally omit horizon distance/pixels-per-revolution from shader state. The earlier Pascal scaling change itself contains an explicit approximation TODO; it should inform a controlled camera/sky regression, not be copied as an exact engine formula.

## Post-audit disposition (2026-09-09)

Re-inspected the changed working-tree source after the initial report. HEAD remained `9d72f4053683e4e556e9c6247a31051fb0fd25e4`; these are subsequent working-tree changes, not newly verified upstream commits. This documentation follow-up ran no builds or tests.

| Finding | Current disposition and limit |
|---|---|
| Legacy six-field JKL editor lights | **Fixed in source.** [JklParser.LoadLights](../../dotnet/src/Sed.Formats/Jkl/JklParser.cs) now accepts exactly six, seven, or ten values, maps legacy intensity-before-range correctly, bounds the declared count, and rejects truncated sections or unsupported row widths. [LegacyEditorLightTests](../../dotnet/tests/Sed.Core.Tests/LegacyEditorLightTests.cs) includes editing/regenerating a section containing both legacy and modern rows. Test execution is reported separately. |
| JK/MotS texture clamp flags | **Preview restriction implemented.** [SceneAssembler.TextureClampMode](../../dotnet/src/Sed.Rendering/SceneAssembler.cs) applies clamp bits only to the IJIM preview; JK/MotS world and model draws use repeat addressing. This derives draw state without changing the authored face flags. File-bit preservation remains separate from renderer interpretation. |
| GUI horizon offsets | **Offset plumbing fixed.** [VulkanView.SetLevel](../../dotnet/src/Sed.App/VulkanView.cs) now passes both horizon offsets to `SetSky`, matching the CLI path. Horizon distance/pixels-per-revolution scaling and complete sky projection parity remain unresolved. |
| Native normalized ARCH model fingerprint | **Preview-only guard implemented.** [ThreeDoParser.Parse(string)](../../dotnet/src/Sed.Formats/ThreeDo/ThreeDoParser.cs) computes the [normalized fingerprint](../../dotnet/src/Sed.Formats/ThreeDo/ArchitectureModelFingerprint.cs); [SceneAssembler.ResolveArchitecture](../../dotnet/src/Sed.Rendering/SceneAssembler.cs) checks an existing native source hash before using a binding. A mismatch or unverifiable fingerprint produces a diagnostic and falls back to base/sector lighting. Normalization strips comments, trims and omits empty lines, and hashes CRLF-terminated ASCII content as UTF-8; non-ASCII, NUL, or overlong source lines return no fingerprint rather than claim Windows code-page equivalence. A missing historical source hash is still accepted under the existing name/shape checks. This does **not** add apply/export-time verification, establish missing historical baselines, or validate every model LOD; those parts of the local Delphi guard remain unported. |

**Still unresolved:** camera-dependent transparent polygon sorting; complete alpha-cutout metadata; sky/authored depth-write state; hierarchy-node type/pivot/name preservation and the root-sibling difference; complete sky scaling; and the remaining ARCH baseline/apply/export/all-LOD checks above. Current translucent draws still follow batch order, the opaque pipeline still writes depth, and the 3DO writer still emits fixed node type/zero pivots/derived names. No general renderer or arbitrary-model round-trip parity is claimed.

## Local Delphi improvements that must be distinguished from upstream

This project's [`6b5bd1da722b7d4e0ad2001469e749ac8eaa3e83`](https://github.com/andreipemberton/SED-MotS/commit/6b5bd1da722b7d4e0ad2001469e749ac8eaa3e83) introduced MotS preservation, game launch profiles, parser/template fixes, and architectural-lighting guards. [`8a3d89b70fc7d31eae5ec978ad1c7f336919f73e`](https://github.com/andreipemberton/SED-MotS/commit/8a3d89b70fc7d31eae5ec978ad1c7f336919f73e) mainly records/builds the Delphi application and tooling. They are not later `smlu` upstream fixes.

| Local Delphi behavior | Current C# mapping / remaining limit |
|---|---|
| Preserve independent MotS mono/RGB, surface extra light, typed ARCH objects and thing bindings, native metadata | Reimplemented in current `Surface.Corner`, `ArchitecturalLightObject`, JKL reader/writer, and `JedImporter`; the C# baseline lacked this preservation. The current C# renderer additionally consumes these channels. No new format-corpus run was performed by this history audit. |
| Capture normalized model-content SHA-256, compare before ARCH export, require exact highest-detail mesh counts and safe coverage of every lower LOD | **Not equivalently ported.** Delphi `ARCHLIGHTING_IO.INC` captures comment-stripped, trimmed model lines, hashes `lines.Text`, then validates the hash and all declared geosets before exporting a binding. C# stores optional `Thing.ArchLightingSourceModelHash`, but inspected consumers copy/report it rather than verify it. C# writer checks object index and model name; renderer checks name and geoset-zero counts. Same-name replacements with unchanged counts are not detected. A resource-aware guard should define compatible text normalization/hash encoding explicitly, verify available native baselines, and distinguish missing baseline from verified match. Do not conflate whole-archive snapshot hashes with a historical model-binding baseline. |
| Resolve model templates through source/global parent chains | Native C# import merges bundled and companion templates; `Level.GetThingModel` follows the resulting library. Its lookup is depth-limited to 32, while the Delphi helper uses cycle tracking with a larger bound. No new failing real template chain was established here. |
| Native plugin `NewLevel(mots)` boolean and template-list lifetime/index repairs | These correct Delphi APIs/data structures. Managed C# plugins have a separate API and memory model; no automatic native ABI compatibility is claimed. Current C# template dependency/copy preservation is implemented separately. |
| Delphi build scripts and compiler evidence | Remain historical Delphi artifacts. They do not establish C# runtime parity or require migrating Delphi build machinery into the modern project. |
