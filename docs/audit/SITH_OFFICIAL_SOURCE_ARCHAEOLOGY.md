# Sith / LucasArts source, SDK and prototype archaeology

Search completed 2026-09-09. **No original LucasArts JKDF2/MotS/LEIA source-code archive or official public Sith level-editor SDK was located.** There is useful original development documentation and credible testimony, together with public reconstructed engines and related-game prototypes. This is a bounded finding about inspected public evidence, not proof that private backups or undiscovered leaks do not exist.

## Original internal tools and documentation

The public JKDF2 archive mirrors a 60-page scan of the **1996 Jedi Knight Technical Design Document**, including *Leia Feature Description*, credited to Yuan Wang and Winston Wolff. Printed pages 46-47 (PDF pages 45-46, visually inspected) describe a Windows 95 editor with sector geometry, a hierarchy view and a running game view; the editor and game are intended to operate simultaneously. The pages carry a LucasArts proprietary/confidential footer dated November 7, 1996. This is original-looking internal documentation, **not an officially released SDK or executable**. The mirror does not establish the acquisition chain or a public license. Original PDF retained with SHA256 in the manifest. [Document mirror](https://jkdf2.net/JKBot/JKArchive/JKDF2/JKDF2/Documents%20And%20Development%20Information/Text/96-11_Jedi_Knight_Technical_Design_Document_compressed-1.pdf)

In a preserved **2015 conversation**, original developer Yves Borckmans states that LEIA was not publicly available, that LucasArts restricted its internal tools, and that he did not take a copy when leaving. He remembers its integrated game view and preferred JED for most editing. Asked whether the JK source was lost, he says he does not know and points out that source control and subsequent games should have produced backups. Thus, the often repeated claim that LucasArts definitely lost the source is **not established by this interview**. This is attributed developer testimony, not an inventory of Disney's archives today. [Interview](https://www.jkdf2.net/articles/yves-borckmans-conversation-2015/)

The **DroidWorks postmortem** by lead programmer Jon Blossom and project leader Collette Michaud is stronger evidence of tool reuse than a fan engine-family diagram. In Game Developer, August 1999, its discussion of inherited JK technology names **LEIA** and the animation previewer/editor **ModelX**, and describes staff experienced with them. PDF pages 36-38 and 41-42 were text-inspected. This demonstrates internal sharing with LucasLearning, not a public tool release. [Original magazine archive](https://media.gdcvault.com/GD_Mag_Archives/GDM_August_1999.pdf)

Also acquired: the mirrored **1997 preliminary MotS script** (21-page scan) and Ryan Kaufman's **MotS production account** (five pages). These are design/production evidence; they do not contain a level-editor source SDK. The scanned script was inventoried without full OCR or content audit. [Script](https://jkdf2.net/JKBot/JKArchive/JKDF2/JKDF2/Documents%20And%20Development%20Information/Text/97-10_MotS_Script_Preliminary.pdf), [production account](https://jkdf2.net/JKBot/JKArchive/JKDF2/JKDF2/Documents%20And%20Development%20Information/Text/MotS_Production_by_Ryan_Kaufman.pdf)

## Official releases and prototypes, with engine boundaries

**Raven's Jedi Outcast tools are a real public SDK lead, but for the later idTech3 games.** Massassi's original April 22, 2002 tool package and its second update were acquired. The first package's notice calls it a public tool release; the second's readme identifies EffectsEd, BehavEd, the ICARUS compiler, RoQ tooling, documents, single-player scripts and VM game-source folders. Passive ZIP inspection found 136 C/C++/header files in the update. The archive contains a separate `code/JK2 Game Source License.doc`; this older SDK must not automatically be treated as the later GPL engine release. Neither package is a Sith/JKDF2/MotS source SDK. [Archive and descriptions](https://www.massassi.net/programs/)

The 2013 Massassi discussions about Raven's source release and LucasArts' closure are useful contemporaneous leads, but claims about missing JK source or copies on former employees' machines remain forum claims without a recovered artifact. [Raven discussion](https://forums.massassi.net/Main_Massassi_Forums/Discussion_Forum/thread_67093_page_1.html), [closure discussion](https://forums.massassi.net/Main_Massassi_Forums/Discussion_Forum/thread_67089_page_1.html), [JKHub project history](https://jkhub.org/wiki/JKHub%3AAbout)

Searched current GitHub publisher pages/APIs, original Massassi programs/plugins and archived forums, JKDF2's document mirror/developer interview, JKHub history, Hidden Palace, TCRF search/index leads and Internet Archive advanced-search metadata. Exact IA queries/results and selected item metadata are saved. Chrome was explicitly requested and attempted through the supported browser API, which returned `Browser is not available: chrome`; browser inventory returned an empty list. The subsequent authorized hidden headless-Chrome attempt was **rejected before execution by automatic approval review with `blocked by policy`**, without a more specific reason. It was not retried. Brave/Mojeek/DDG web-open attempts were unavailable, so this report does not claim successful Chrome or alternate-engine browsing. Read-only web/HTTP fallback was used. ModDB challenged downloads; the JKDF2 parent directory returned 403 while the known public PDFs were accessible; TCRF page fetches failed. No access control or CAPTCHA was bypassed.

The machine-readable manifest `SITH_OFFICIAL_SOURCE_ARCHAEOLOGY.json` links the exact document hashes, repository pins, archive metadata, collection manifests and unresolved/access-blocked entries. Downloads are passive external research material; no legacy or prototype program was run, and no third-party assets or unclearly licensed code were added to the editor release.
