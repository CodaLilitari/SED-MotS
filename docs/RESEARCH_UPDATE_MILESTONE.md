# Research and update milestone

Status: in progress, 2026-09-30. This document records the authorized next slice;
it does not certify a build or publication before the evidence is added.

## Acceptance

1. GUI, CLI and MCP report dynamic vertex-color readiness from the exact JKL
   output the writer would save, including unchanged retained source sections.
   Report source revision, output hash and separate retail/current OpenMotS
   conclusions. No automatic RGB perturbation or runtime-parity claim.
2. The Windows editor checks versioned update metadata, verifies package size
   and SHA256, and stages an update in a new directory. It must preserve the
   current editor, unsaved-work decisions and existing user files. Numeric
   prerelease comparison, channel selection and hostile ZIP cases are tested.
3. The portfolio hosts the small feed and curated research bundle where its
   existing static hosting supports them. GitLab hosts large Windows packages
   and alternate feeds. Publication requires anonymous byte/hash verification.
4. A private, provenance-indexed corpus references research files in place.
   Acquisition, reading, source verification, runtime evidence and reuse rights
   are distinct. Raw community captures never enter the public source or bundle.
5. A reusable `jk-mots-level-workflow` Codex skill connects evidence retrieval to
   shared SED authoring operations. Its curated reference updater preserves
   private evidence, local notes and executable workflow files.
6. Build, focused counterexamples, packaged CLI/MCP workflows, distribution
   provenance and independent review are completed before release claims.

## Contracts

The inspected retail four-channel compaction predicate compares final float32
white/red/green values for every corner; blue does not participate. One unequal
corner preserves the surface RGB allocation. Scalar-row retail behavior remains
unverified. Current OpenMotS retains four-channel data by row layout. These are
bounded source/binary observations, not a new retail gameplay result.

Editor feed: `/updates/sed/releases.json` on the portfolio, with GitLab raw
`updates/sed-releases.json` as fallback. The feed is data, never commands.
The current package series uses preview versions; stable and preview are explicit.

Research feed: `/projects/jk-mots-level-workflow/research-updates.json` on the
portfolio, with GitLab raw `updates/research-updates.json` as fallback. Only
allowlisted, hash-verified reference files can be updated through this route.

The existing PLAY-01 reviewer/release handoff remains paused. This milestone
does not silently resume its provider polling or claim acceptance of that work.
